# 自動補題排程修正（2026-11-18）

狀態：本機修改與模擬測試通過；尚未讀取、更新或驗收線上 GAS。Git 原始碼不代表目前部署版本。

本次修正：

- 從函式入口共用 240 秒時間預算，查證預留 45 秒保存時間；在維護題庫前取得執行租約，避免重疊排程先做重複工作。
- 此入口每輪最多整理兩份課程佇列，不額外產生未驗證 AI 候選答案；仍沿用課程答案頁優先的查證流程。獨立維護入口行為保留。
- 每題開始前保存課程與題目位置；成功提交 Git 後才清除該題階段暫存。未跑完的課程優先續跑，已提交的題目由持久狀態排除。
- 已完成的研究／複核 API 回覆按題目與策略暫存一天，UTF-8 大於 8 KB 時不存入 Properties。暫存過大、過期或 API 回覆後尚未寫入便中止，仍可能再次付費呼叫；不保證恰好一次。
- 每輪最多三題、每日最多 48 題，依當日剩餘額度縮小批次；先預扣配額，因此中止可能少用，不會自動補回。
- 區分讓出時間、租約失效、服務錯誤、API 權限／設定問題與回覆格式錯誤。服務錯誤不增加來源核實次數，延遲由 15 分鐘逐步增加至一天，連續五次後轉待人工檢查。設定與格式錯誤也須人工檢查後恢復，不自動盲目重試。
- 答案、佇列、題庫版本維持單一 Git 提交與非強制更新；競爭失敗不推進游標。保存鎖忙碌不再當作已處理零題。

驗證：執行 backend/test*.cjs 全部八組測試；新增共用期限、入口租約、每日最後一格配額、付費階段跨輪重用、租約遺失、讓出位置、保存忙碌與模板一致性測試。測試使用替身，不呼叫付費 API 或改動正式題庫。

限制：同步 UrlFetch 無法被 JavaScript 時間檢查取消，因此仍可能被單次慢請求拖過期限，不能保證完全消除 GAS 逾時。Telegram 仍是每輪提交後通知，尚未加入持久通知 outbox，不能保證當次程序被強制終止時通知一定送達。獨立 maintainEcpaReviewQueue 入口不是本次全程預算驗收範圍。
